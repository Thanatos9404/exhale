# Accessibility

The target is WCAG 2.2 level AA. This page lists the success criteria Exhale can back with both a source file and an automated test, and ends with what that evidence does not cover.

## How it is checked

## Motion and themes

**Reduced motion.** With `prefers-reduced-motion: reduce`:

- A global rule cuts every CSS animation and transition to 1 ms and disables smooth scrolling ([utilities.css](src/styles/utilities.css)).
- Collapsible panels fade without animating their height ([useCollapse.ts](src/components/useCollapse.ts), [BuildLogs.tsx](src/pages/routine/BuildLogs.tsx)).
- The tab indicators jump instead of sliding ([Tabs.tsx](src/components/shell/Tabs.tsx)).
- The 3D scenes stop their frame loop and auto-rotation, and the 2D canvases draw a still frame ([AirColumn.tsx](src/components/three/AirColumn.tsx), [ParticleDonut.tsx](src/components/three/ParticleDonut.tsx), [ParticleOrb.tsx](src/components/ParticleOrb.tsx)).
- Pulsing dots and skeletons stop ([status.tsx](src/components/ui/status.tsx)).

[a11y.test.tsx](src/pages/a11y.test.tsx) renders every route with the preference on, checks that routine details open with no height animation, and checks the opposite without the preference so the test is meaningful. The whole Playwright suite runs with reduced motion, and [e2e/motion.spec.ts](e2e/motion.spec.ts) repeats key journeys with animations on.

**Themes.** Dark and light are separate token sets in [index.css](src/styles/index.css), and a "System" option follows the OS setting. The choice is applied before first paint by [theme-init.js](public/theme-init.js) and stored in the browser. The theme switch is a radio group. [e2e/accessibility.spec.ts](e2e/accessibility.spec.ts) audits every route in both themes and proves the switch works from the keyboard and survives a reload.

**Forced colours.** [forced-colors.css](src/styles/forced-colors.css) redraws what Windows High Contrast removes: focus outlines, control boundaries, the selected radio and tab, switch states, status dots, checkboxes and sliders, using system colours only. [tests/contrast.test.ts](tests/contrast.test.ts) asserts that each of those selectors is present and that the block contains no theme token and no literal colour.

## Languages

The interface is in English and the document is `lang="en"` ([index.html](index.html)). The community bulletin on the Routine page can be shown in Hindi. Its text is then marked `lang="hi"`, as is the "हिन्दी" option of the language switch, so a screen reader can change voice ([CommunityAdvisoryCard.tsx](src/pages/routine/CommunityAdvisoryCard.tsx)). ## Known issues and limits of this evidence

**Known axe issues: none open.** The `KNOWN_ISSUES` allow-list in [e2e/support/axe.ts](e2e/support/axe.ts) is empty, so any axe violation in Chrome fails the suite. It used to hold two entries. Both are fixed in the source:

**Limits.**

- **No manual screen-reader pass has been recorded.** Nothing here was verified by a person using NVDA, JAWS, VoiceOver or TalkBack. Names, roles and live regions are asserted through the accessibility tree, which is not the same as hearing them.
- **Automated rules find only part of WCAG.** A clean axe run does not prove conformance.
- **Forced colours was checked through Chrome emulation only**, not on Windows High Contrast with a real theme. On 24 November 2026 the Settings and Indoor lab pages were loaded in Chrome with forced colours emulated, and the computed styles showed the system highlight colour on the focus outline, the checked switch and the selected radio. That check is not part of the suite. The automated test checks that the rules exist, not how they render.
- **jsdom cannot compute contrast.** That is why contrast is computed from the tokens, and checked again by axe in real Chrome. The token table covers the pairings it lists. A colour used outside the tokens would be caught only by the Chrome audit, and only on the screens that audit opens.
- **Reflow is automated at 390 CSS pixels, not at 320.** WCAG 1.4.10 names 320. No automated test covers that width.
- **Not tested:** 200% text resize (1.4.4), text spacing overrides (1.4.12), focus hidden behind the sticky tab bar (2.4.11), and input purpose (1.3.5). The household form sets no `autocomplete` attributes.
- **Target sizes are read from class names in jsdom**, not measured in a browser. axe's `target-size` rule is off by default and is not switched on.
- **The hour strip on Overview has cells narrower than 24 CSS pixels on a phone.** The slider above it performs the same function with a 24 pixel tall target.
- **Rotating the 3D air column by dragging is pointer only.** The rotation is decorative and changes no information.
- **Keyboard tests cover Chrome and jsdom.** Other browsers and switch or voice input are not tested.
- **Toasts come from a third-party library** and are tested only for their text and their notification region.
